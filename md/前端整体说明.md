# ant-js 前端整体说明

这份文档给新同学快速建立项目全貌，重点讲清楚三件事：

1. 这个项目的“前端”到底是什么。
2. Android 原生层和页面层如何通信。
3. 页面层如何驱动任务、日志和设备能力。

## 1. 项目定位

这个项目不是传统意义上的纯前端 App，而是一个“Web 前端 + Android 容器 + Rhino 脚本引擎”的混合自动化项目。

整体可以拆成三层：

1. 页面层：通过 WebView 加载远端管理后台页面，负责配置任务、展示日志、控制启动停止。
2. 原生层：负责权限、服务保活、悬浮窗、截图、存储、Shell、OCR 等系统能力。
3. 脚本层：通过 Rhino 执行远端 JS 脚本，完成自动化逻辑。

对新同学来说，可以把它理解为：

- 页面层是“控制台”。
- 原生层是“设备能力适配器”。
- Rhino 脚本层是“真正跑任务的执行器”。

## 2. 启动链路

### 2.1 启动顺序

应用启动后，主链路大致如下：

1. `LaunchActivity`
2. `MainActivity`
3. `Browser` 初始化 X5 WebView
4. 页面加载远端地址
5. `TaskService` 常驻，等待页面或脚本触发任务

### 2.2 LaunchActivity 在做什么

`LaunchActivity` 不是业务页面，而是进入应用前的授权检查页。它会检查：

1. Root 权限
2. 悬浮窗权限
3. 存储权限
4. 应用列表权限
5. 系统截图权限（mediaProjection）

其中系统截图是否需要，取决于当前截图模式。

### 2.3 MainActivity 在做什么

`MainActivity` 负责：

1. 初始化 `Browser`
2. 启动 `TaskService`
3. 写入屏幕宽高和 dpi 到 MMKV
4. 检查悬浮窗、存储和截图授权

可以把它看成“原生容器入口”。

## 3. 页面入口和配置

### 3.1 页面从哪里加载

`Browser` 会优先从 MMKV 读取 `BASE_URL`，如果没有，就退回到 `BuildConfig.BASE_URL`。

这意味着页面地址有两种来源：

1. 编译时 flavor/buildType 注入的默认地址
2. 运行时通过 MMKV 覆盖后的地址

### 3.2 失败回退

如果入口地址是本地开发地址，并且加载失败，`Browser` 会尝试回退到 `BuildConfig.FALLBACK_BASE_URL`。

这对联调很重要：

1. 本地服务挂掉时，应用不一定白屏。
2. 页面可能自动切到备用地址。

### 3.3 多渠道差异

项目通过 product flavor 区分不同发行渠道，例如：

1. `ant`
2. `cht`
3. `jiuzhuan`
4. `jingwei`
5. `168h`

不同 flavor 会影响：

1. `applicationId`
2. `BASE_URL`
3. `FALLBACK_BASE_URL`
4. `WEB_API_URL`
5. `IS_REQUIRE_PACKNAME`
6. 应用名和 logo

前端如果出现“同一套代码在不同包表现不一致”，先看是不是 flavor 配置差异。

## 4. 页面层和原生层通信

### 4.1 通信方式

`Browser.registerApi()` 通过 `addJavascriptInterface` 向页面注入原生桥对象。

页面可以直接调用这些对象：

1. `_base`
2. `_js`
3. `_log`
4. `_mmkv`
5. `_toast`
6. `_shell`
7. `_device`

## 5. 页面桥 API 一览

下面只写页面最常用的能力。

### 5.1 `_base`

基础应用信息和外链能力。

常用方法：

1. `getPackageName()` 获取当前 App 包名
2. `getAppVersionCode()` 获取版本号 code
3. `getAppVersionName()` 获取版本名
4. `getAppName()` 获取应用名
5. `openUrl(url)` 打开外部链接
6. `exit()` 直接退出应用
7. `getInstalledApps()` 获取已安装应用包名列表
8. `changeNet(type)` 切换网络策略并写入 MMKV
9. `getBuildConfig()` 获取当前包的 BuildConfig 配置，默认导出全部静态字段，但会过滤掉 `Android_` 前缀字段（大小写不敏感）；返回 JSON 字符串，key 与 BuildConfig 字段名一致

页面示例：

```js
const appName = _base.getAppName();
const version = _base.getAppVersionName();
const buildConfig = JSON.parse(_base.getBuildConfig());
_log.addLog(`当前应用: ${appName} ${version}`);
_log.addLog(`当前接口地址: ${buildConfig.WEB_API_URL}`);
```

### 5.2 `_js`

任务控制桥，页面侧最常用。

常用方法：

1. `isRunning()` 当前任务是否运行中
2. `start()` 启动任务
3. `stop()` 停止任务
4. `gc()` 触发一次 GC
5. `openFloat()` 打开悬浮窗服务
6. `changeFloat(position)` 调整悬浮窗位置
7. `restartApp()` 重启当前应用
8. `getIpInfo(ip)` 查询 IP 信息

页面示例：

```js
function toggleTask() {
  if (_js.isRunning()) {
    _js.stop();
    _log.addLog('任务已停止');
  } else {
    _js.start();
    _log.addLog('任务已启动');
  }
}
```

### 5.3 `_log`

写日志、查日志。

常用方法：

1. `d(message)`
2. `e(message)`
3. `v(message)`
4. `addLog(message, level, showFloatToast)`
5. `getLogs(startTime, endTime, pageSize, page, callbackId)`
6. `getLogsByDay(day, pageSize, page, callbackId)`
7. `clearLogs()`

注意：`getLogs` 的结果不是同步返回，而是回调给页面里的：

`window.handleLogsResult(callbackId, result)`

`getLogs` 里的 `startTime` 和 `endTime` 使用毫秒时间戳；如果传反了，原生层会自动按较小值作为开始时间、较大值作为结束时间。

`getLogsByDay` 是兼容入口，内部会自动换算成“最近 N 天”的时间区间。

回调里的 `result` 现在是一个分页对象：

```js
{
  list: [
    {
      id: 123,
      timestamp: 1714012345678,
      level: 'normal',
      message: '页面初始化'
    }
  ],
  page: 1,
  pageSize: 20,
  total: 58,
  pageCount: 3,
  error: null
}
```

字段说明：

1. `list`：当前页日志列表
2. `page`：当前页码，从 `1` 开始
3. `pageSize`：当前每页条数
4. `total`：查询范围内的日志总数
5. `pageCount`：总页数
6. `error`：异常时返回错误信息，正常时为空

页面示例：

```js
const endTime = Date.now();
const startTime = endTime - 7 * 24 * 60 * 60 * 1000;

window.handleLogsResult = function (callbackId, result) {
  if (result.error) {
    console.error('日志查询失败', callbackId, result.error);
    return;
  }

  console.log('日志结果', callbackId, result.list);
  console.log('分页信息', result.page, result.pageCount, result.total);
};

_log.getLogs(startTime, endTime, 20, 1, 'init-log-list');
```

### 5.4 `_mmkv`

页面持久化存储桥，适合保存页面配置、地址、用户状态。

常用方法：

1. `put(key, value)`
2. `get(key)`
3. `putString(key, value)`
4. `getString(key)`
5. `getBoolean(key)`
6. `getInt(key)`
7. `getFloat(key)`
8. `getLong(key)`
9. `containsKey(key)`
10. `remove(key)`
11. `clearAll()`

页面示例：

```js
const baseUrl = _mmkv.getString('BASE_URL');
if (!baseUrl) {
  _mmkv.putString('BASE_URL', 'http://example.com/auto/ui/');
}
```

### 5.5 `_toast`

原生 Toast 提示。

常用方法：

1. `showShort(text)`
2. `showLong(text)`
3. `toast(text, isLong)`

### 5.6 `_shell`

页面直连 Shell 的能力，建议谨慎使用。

常用方法：

1. `cmd(args)`
2. `fastCmd(args)`

建议：

1. 只用于文本型命令
2. 不要在页面层直接拿它做二进制截图
3. 输入事件、查询命令可以用

### 5.7 `_device`

设备信息桥。

常用方法：

1. `getUUID(prefix)`
2. `getAndroidID()`
3. `getInfo()`

## 6. 前端同学需要知道的数据流

### 6.1 页面发起任务

最常见链路：

1. 页面点击“开始”
2. 调用 `_js.start()`
3. 原生层发 `TaskEvent(START_TASK)`
4. `TaskService` 收到事件后重启任务
5. Rhino 拉取脚本并执行

### 6.2 页面停止任务

1. 页面点击“停止”
2. 调用 `_js.stop()`
3. 原生层发 `TaskEvent(STOP_TASK)`
4. `TaskService` 中断脚本线程

### 6.3 页面查看日志

1. 页面调用 `_log.getLogs(startTime, endTime, ...)`
2. 原生层从 Room 取日志
3. 原生层同时计算 `total` 和 `pageCount`
4. 通过 `window.handleLogsResult(...)` 回传分页对象给页面

## 7. 页面层与脚本层的职责分工

这是新人最容易混淆的点。

### 页面层适合做的事

1. 配置任务列表
2. 展示状态和日志
3. 保存后台地址、用户配置
4. 控制启动、停止、重启
5. 做后台管理和调试辅助

### 脚本层适合做的事

1. 启动目标 App
2. 点击、滑动、按键
3. 截图和找图
4. OCR
5. 页面判断
6. 自动化流程控制

原则上，不要把复杂自动化逻辑写在页面 JS 里，而应该写在 Rhino 脚本里。

## 8. 关键服务

### 8.1 `TaskService`

脚本执行服务。它是 Rhino 宿主，负责：

1. 注册脚本 API
2. 拉取远端任务脚本
3. 在后台线程执行 JS
4. 中断和切换任务
5. 定时任务重启

### 8.2 `FloatService`

悬浮窗服务，主要用于：

1. 显示运行状态
2. 快捷启停任务
3. 展示浮层消息

### 8.3 `ProjectionCaptureService`

当截图模式为 `mediaProjection`，也就是界面里的“系统截图”时，负责维持截图通道。

## 9. 新人接手页面开发的建议

1. 先把 `Browser` 的注入桥对象摸熟，再改页面逻辑。
2. 页面里所有“开始任务/停止任务/看日志”都优先走现有桥，不要重复造协议。
3. 配置类数据优先放 MMKV，避免只存在前端内存里。
4. 自动化动作不要写死在页面逻辑里，尽量交给脚本引擎。
5. 联调失败时，先确认当前 flavor、入口 URL、MMKV 中的 `BASE_URL` 是否一致。

## 10. 一个典型页面示例

```js
function initPage() {
  const appName = _base.getAppName();
  const versionName = _base.getAppVersionName();
  const deviceInfo = _device.getInfo();
  const endTime = Date.now();
  const startTime = endTime - 3 * 24 * 60 * 60 * 1000;

  _log.addLog(`页面初始化: ${appName} ${versionName} ${deviceInfo}`);
  _log.getLogs(startTime, endTime, 20, 1, 'home-init');
}

function startTask() {
  _toast.showShort('准备启动任务');
  _js.start();
}

function stopTask() {
  _toast.showShort('准备停止任务');
  _js.stop();
}

window.handleLogsResult = function (callbackId, result) {
  if (result.error) {
    console.error('log callback failed', callbackId, result.error);
    return;
  }

  console.log('log callback', callbackId, result.list);
  console.log('page info', result.page, result.pageCount, result.total);
};
```

## 11. 常见排查顺序

当前端页面出现问题，建议按这个顺序排查：

1. 当前包是不是预期 flavor
2. 当前入口 URL 是不是预期地址
3. 页面桥对象有没有成功注入
4. Root/悬浮窗/存储/截图权限是否满足
5. `TaskService` 是否已启动
6. 日志是否已写入 Room
7. 问题是在页面层，还是在脚本执行层

## 12. 一句话总结

这个项目的“前端”本质上是一个运行在 WebView 里的控制后台，负责把配置和指令送到原生层；真正执行自动化的是 `TaskService + Rhino 脚本引擎`。
