# ant-js 脚本引擎说明

这份文档给新来的实习生快速理解项目里的脚本执行机制、可调用 API 和常见写法。

如果你是临时查方法，不想先看完整说明，可以直接看同目录下的《脚本引擎API速查表》。

如果只记住一句话：

这个项目里的脚本，是远端下发的 JavaScript，通过 Rhino 在 Android 本地执行，脚本负责直接驱动自动化任务。

## 1. 脚本引擎是什么

项目使用 Rhino 作为 JavaScript 运行时。`TaskService` 会：

1. 从 MMKV 读取任务列表
2. 按任务里的 `packageName` 拼接脚本 URL
3. 拉取远端 JS 源码
4. 注册一组原生对象到 JS 全局作用域
5. 在独立线程中执行脚本

所以业务脚本并不打包在 APK 内，而是运行时拉取。

## 2. 脚本执行链路

一次任务启动的大致流程如下：

1. 页面或悬浮窗调用开始任务
2. 原生层发送 `TaskEvent(START_TASK)`
3. `TaskService` 停掉旧任务，创建新的 Rhino 上下文
4. 注册 `app`、`global`、`image` 等对象
5. 从 MMKV 读取任务列表 `taskList` 或 `txList`
6. 取第一条任务作为当前任务
7. 根据 `jsUrl + packageName + ".js"` 拉取脚本
8. 执行脚本

切任务时，调用 `global.next()` 或原生事件，会把当前任务从列表头部移除，再继续下一条。

## 3. 脚本运行时可用对象

Rhino 执行时，当前全局作用域里会注册这些对象：

1. `app`
2. `display`
3. `global`
4. `keys`
5. `log`
6. `ocr`
7. `shell`
8. `image`
9. `storages`
10. `toast`
11. `require`

脚本里直接用，不需要 import。

例如：

```js
log.addLog('脚本开始执行', true);
toast.shortToast('开始跑任务');
```

## 4. 最常用 API 分类

### 4.1 `global` 通用控制与触控

#### 常用方法

1. `global.log(message)`
2. `global.sleep(millis)`
3. `global.sleep(min, max)`
4. `global.random(min, max)`
5. `global.inPage(str)`
6. `global.getCurrentPackage()`
7. `global.getCurrentActivity()`
8. `global.getCurrentActivityWithPackage()`
9. `global.click(x, y)`
10. `global.longClick(x, y, duration)`
11. `global.press(x, y, duration)`
12. `global.swipe(x1, y1, x2, y2, duration)`
13. `global.start()`
14. `global.stop()`
15. `global.next()`
16. `global.download(url, path)`
17. `global.installApk(path)`
18. `global.uninstallApk(packageName)`
19. `global.restartApp()`
20. `global.changeFloat(position)`
21. `global.cacheScreenshot()`
22. `global.getScreenshotImage()`

#### 典型用途

- `sleep` 用于等待页面稳定
- `inPage` 用于判断当前页面是不是目标页面
- `getCurrentPackage` / `getCurrentActivity` 用于兜底判断前台状态
- `click` / `swipe` / `press` 是最基础的交互能力
- `next` 用于当前任务完成后切下一条

#### 示例

```js
if (!global.inPage('com.example.app')) {
  app.launchPackage('com.example.app');
  global.sleep(3000);
}

global.click(540, 1800);
global.sleep(800, 1200);
```

### 4.4 `log` 日志

#### 常用方法

1. `log.d(message)`
2. `log.e(message)`
3. `log.v(message)`
4. `log.addLog(message, showFloatToast, level)`

#### 建议

1. 业务关键节点都写 `log.addLog`
2. 失败分支一定打日志
3. 不要只依赖 `console` 思维，Rhino 脚本主要看原生日志和数据库日志

#### 示例

```js
log.addLog('准备进入签到流程', true);
```

### 4.5 `toast` 提示

#### 常用方法

1. `toast.shortToast(text)`
2. `toast.langToast(text)`

注意：这里的方法名是 `langToast`，不是 `longToast`。

### 4.6 `shell` Shell 命令

#### 常用方法

1. `shell.cmd(args)`
2. `shell.fastCmd(args)`
3. `shell.sleepScreen()`

#### 使用建议

1. 适合执行文本型命令，例如 `dumpsys`、`pm`、`am`、`input`
2. 不建议直接拿来做 `screencap -p` 这种二进制输出命令
3. 如果已有原生 API，就优先用原生 API，不要手搓 Shell 替代

#### 示例

```js
const currentFocus = shell.fastCmd('dumpsys window | grep mCurrentFocus');
log.addLog(`当前焦点: ${currentFocus}`, false);
```

### 4.7 `display` 屏幕信息

#### 常用方法

1. `display.getDisplayWidth()`
2. `display.getDisplayHeight()`
3. `display.getDisplayDensityDpi()`

#### 示例

```js
log.addLog(
  `屏幕: ${display.getDisplayWidth()}x${display.getDisplayHeight()} dpi=${display.getDisplayDensityDpi()}`,
  false
);
```

### 4.8 `storages` 本地持久化

#### 常用方法

1. `storages.put(key, value)`
2. `storages.get(key)`
3. `storages.putString(key, value)`
4. `storages.getString(key)`
5. `storages.getBoolean(key)`
6. `storages.getInt(key)`
7. `storages.getFloat(key)`
8. `storages.getLong(key)`
9. `storages.containsKey(key)`
10. `storages.remove(key)`
11. `storages.clearAll()`

#### 建议

1. 保存脚本运行标记、重试次数、冷却时间
2. 配置数据尽量用明确的 key
3. 新脚本优先用字符串和布尔值，避免多端联调时类型误差

#### 示例

```js
const key = 'daily_sign_done';
if (storages.getBoolean(key)) {
  log.addLog('今天已经签到过，切下一个任务', true);
  global.next();
}

storages.put(key, true);
```

### 4.9 `ocr` 文字识别

#### 常用方法

1. `ocr.recognizeText(path)` 返回纯文本
2. `ocr.recognizeTextAsJson(path)` 返回带框信息的 JSON

#### 示例

```js
const imgPath = image.takeCapture('ocr_area', '100,200,500,220');
const text = ocr.recognizeText(imgPath);
log.addLog(`OCR 结果: ${text}`, true);
```

## 5. `image` 图像能力

这是这个项目里最核心、也最容易出问题的一块。

### 5.1 能力概览

`image` 主要负责：

1. 截图
2. 模板匹配
3. 灰度模板匹配
4. 多目标找图
5. 颜色查找
6. 四角坐标查找

### 5.2 最常用方法

1. `image.getFindImageReturnMode()`
2. `image.getFindImageReturnModeLabel()`
3. `image.toggleFindImageReturnMode()`
4. `image.getFindImageCompareStatsText()`
5. `image.resetFindImageCompareStats()`
6. `image.takeCapture(id, area)`
7. `image.findImage(id, template, threshold)`
8. `image.findImageG(id, template, threshold)`
9. `image.findImages(id, template, threshold, maxMatches)`
10. `image.findImagesG(id, template, threshold, maxMatches)`
11. `image.findColors(template, color, threshold)`
12. `image.findImageCorners(id, template, threshold)`
13. `image.findImageCornersG(id, template, threshold)`

### 5.3 截图模式

当前项目存在多种截图来源：

1. `shell`
2. `screenCapture`，界面显示为“底层截图”
3. `mediaProjection`，界面显示为“系统截图”

当前主返回模式由 `image.getFindImageReturnMode()` 决定。

注意：

1. `mediaProjection` 模式，也就是界面里的“系统截图”，需要额外授权
2. `findImage` 目前会按配置选择主链路
3. 对比链路统计能力已经内置，用于分析不同截图来源的差异

### 5.4 `takeCapture(id, area)` 怎么用

#### 参数说明

1. `id`：截图标识，最终通常会落到缓存目录里的 `<id>.jpg`
2. `area`：裁剪区域，格式为 `x,y,width,height`

#### 返回值

返回保存后的图片路径，失败时返回空字符串。

#### 示例

```js
const fullPath = image.takeCapture('full_page', '');
const btnPath = image.takeCapture('btn_login', '380,1620,320,120');
log.addLog(`截图完成: ${fullPath} / ${btnPath}`, false);
```

### 5.5 `findImage` 和 `findImageG` 的区别

可以先按这个简单理解：

1. `findImage`：彩色模板匹配主入口
2. `findImageG`：灰度模板匹配主入口

灰度匹配在一些光照变化、色偏场景下更稳定，彩色匹配在颜色信息强时更直接。

### 5.6 `id` 参数的真实语义

这是新人最容易误解的点。

在 `findImage*` 系列里，`id` 不只是一个数字编号，它可能表示：

1. 直接文件路径
2. `cache/<id>.jpg` 这类缓存截图 id
3. 空字符串，表示让引擎直接走当前实时截图链路

简单记法：

1. 想匹配当前屏幕，传空字符串 `''`
2. 想匹配你之前截下来的局部图，传对应 `id`

### 5.7 `findImage` 返回什么

返回一个点对象，匹配成功时通常可直接取：

1. `point.x`
2. `point.y`

匹配失败返回 `null`。

#### 示例

```js
const point = image.findImage('', 'task/login_btn.png', 0.85);
if (point) {
  global.click(parseInt(point.x), parseInt(point.y));
  global.sleep(1500);
} else {
  log.addLog('未找到登录按钮', true, 'error');
}
```

### 5.8 多点查找

如果一个页面上有多个相同目标，使用：

1. `image.findImages(...)`
2. `image.findImagesG(...)`

#### 示例

```js
const points = image.findImagesG('', 'task/coin.png', 0.88, 5) || [];
for (let i = 0; i < points.length; i++) {
  const p = points[i];
  global.click(parseInt(p.x), parseInt(p.y));
  global.sleep(500, 800);
}
```

### 5.9 四角点查找

如果你需要的不是中心点，而是匹配区域的四个角，可以使用：

1. `image.findImageCorners(...)`
2. `image.findImageCornersG(...)`

返回的是 JSON 字符串，需要自己解析。

#### 示例

```js
const cornersJson = image.findImageCornersG('', 'task/panel.png', 0.9);
if (cornersJson) {
  const corners = JSON.parse(cornersJson);
  log.addLog(`找到面板四角: ${cornersJson}`, false);
}
```

## 6. `require` 怎么用

Rhino 里内置了一个 `require` 函数，它会把你传入的 URL 拉取下来，然后直接在当前上下文执行。

这更像“远端脚本 include”，不是 Node.js 那种模块系统。

#### 示例

```js
require('http://example.com/common/base.js');
require('http://example.com/common/sign.js');
```

建议：

1. 公共方法可以拆到公共脚本里
2. 业务脚本保持主流程简洁

## 7. 一个完整脚本示例

下面给一个适合新人理解的完整示例，演示常见流程：启动 App、判断页面、找按钮、点击、记录结果、切换任务。

```js
function ensureApp(pkg) {
  if (global.getCurrentPackage() !== pkg) {
    log.addLog(`尝试启动应用: ${pkg}`, true);
    app.launchPackage(pkg);
    global.sleep(5000);
  }
}

function tapIfFound(template, threshold) {
  const point = image.findImageG('', template, threshold);
  if (!point) {
    return false;
  }

  global.click(parseInt(point.x), parseInt(point.y));
  global.sleep(1200, 1800);
  return true;
}

function main() {
  const pkg = 'com.example.demo';
  ensureApp(pkg);

  log.addLog('脚本启动成功，开始执行主流程', true);

  if (global.inPage(pkg)) {
    log.addLog(`当前已在目标应用: ${global.getCurrentActivityWithPackage()}`, false);
  }

  if (tapIfFound('task/home_sign_btn.png', 0.86)) {
    log.addLog('已点击签到按钮', true);
  } else if (tapIfFound('task/home_receive_btn.png', 0.86)) {
    log.addLog('已点击领取按钮', true);
  } else {
    const shot = image.takeCapture('home_debug', '');
    log.addLog(`页面未命中目标按钮，已保存截图: ${shot}`, true, 'warn');
  }

  const flagKey = 'demo_task_finished';
  storages.put(flagKey, true);
  toast.shortToast('当前任务完成，准备切换');
  global.next();
}

main();
```

## 8. 调试建议

### 8.1 先看什么日志

建议先看：

1. `log.addLog(...)` 写入的业务日志
2. `findImage` / `findImageG` 相关识别日志
3. 当前截图模式和识别统计
4. 当前包名、当前 Activity

### 8.2 找图失败时怎么排查

按这个顺序：

1. 模板路径是否正确
2. 当前 `resUrl` 是否正确
3. 当前截图模式是什么
4. 阈值是否过高
5. `id` 是不是传错了
6. 当前页是否真的稳定
7. 是否需要先截图保存做人工对比

### 8.3 OCR 失败时怎么排查

1. 先确认截图是否成功
2. 再确认裁剪区域是否正确
3. 尽量让 OCR 区域只保留文本主体

## 9. 当前代码里几个要特别注意的点

这些不是“脚本写法”，而是你在联调时要心里有数的实现细节。

1. `shell` 更适合文本命令，不适合直接处理截图二进制流。
2. `mediaProjection` 模式，也就是界面里的“系统截图”，必须先完成授权，否则截图链路会失败。
3. `findImage*` 的模板文件会走本地缓存，不是每次都重新下载。
4. `takeCapture`、`findImage`、`findImages` 这类图像方法带同步控制，高频调用要注意节奏。
5. `toast` 的长提示方法名当前是 `langToast`，调用时别写错。

## 10. 写脚本的建议

1. 每个关键分支都打日志。
2. 页面跳转后先 `sleep`，再找图，不要连续硬点。
3. 优先用 `global.getCurrentPackage()` 和 `global.inPage()` 做状态判断。
4. 找图失败时保留截图，方便回溯。
5. 公共逻辑抽到远端公共脚本，用 `require` 复用。
6. 一段脚本只做一件明确的业务流程，不要写成超长巨石脚本。

## 11. 一句话总结

脚本层的职责就是：拿到设备能力后，稳定地把业务流程自动执行完。你写的不是普通前端 JS，而是“跑在 Android 设备上的自动化执行脚本”。
